# Segmentation 參數詳解(為什麼這樣設定)

> 這份文件從零解釋「源遮罩(source mask / segmentation)」每個參數的**物理理由**。
> 假設讀者對天文影像不熟,所以每個名詞都會先解釋。
> 對應程式:`src/run_zap_compare.py` 的 `cmd_mask`;摘要見 `CLAUDE.md`。

---

## 0. 先搞懂:我們在做什麼、為什麼需要遮罩

### 0.1 大背景 — sky reconstruction
我們的目標是「**扣天空**」:望遠鏡拍到的每個像素 = **天體的光 + 天空的光 + 雜訊**。
天空(大氣輝光、月光散射等)是我們**不想要**的,要把它扣掉,只留天體。

做法(sky reconstruction):**先從「只有天空、沒有天體」的區域,學出天空長什麼樣,再把它從整張圖扣掉。**

### 0.2 為什麼需要「源遮罩」
要「從只有天空的區域學天空」,就必須先知道**哪裡有天體、哪裡是純天空**。
- **源遮罩(source mask)** = 一張標記圖:天體所在的像素標 1,純天空標 0。
- 學天空時只用標 0 的地方;標 1 的天體區域被「遮住」不參與。

**如果遮罩沒做好**(把有天體的地方誤當純天空),學出來的「天空」就會混進天體的光 → 扣天空時把天體也扣掉 → 毀掉我們要的科學訊號。**所以遮罩的品質直接決定成敗。**

### 0.3 這個場(Haro11)的難點
Haro11 是一個有**大範圍延展電離氣**的星系 —— 除了中央亮核,周圍還有一大團又暗又散的 **Hα 暈**(halo)。
- 這團暈**每個像素都很暗**(低表面亮度),暗到接近雜訊。
- 但它是**真實的天體光**,必須遮住,否則會污染天空。
- 「怎麼可靠地遮住這種又大又暗的暈」正是所有參數要解決的核心問題。

## 1. 幾個必備名詞(先讀這段)

| 名詞 | 白話解釋 | 這批資料的值 |
|---|---|---|
| **pixel(像素)** | 影像的最小方格 | — |
| **pixel scale(像素尺度)** | 一個像素在天上對應多大角度 | **0.2 角秒/像素** |
| **arcsec(角秒, ″)** | 天上的角度單位。1 度 = 3600 角秒 | — |
| **PSF(點擴散函數)** | 一個「點光源」(如恆星)被大氣+望遠鏡糊開後的樣子。理想是一點,實際是一小團 | — |
| **seeing(視寧度)** | 大氣擾動把影像糊開的程度,用 PSF 的寬度量。**越小越清晰** | **≈1.2 角秒** |
| **FWHM(半高全寬)** | 量「一團東西多寬」的標準方法:亮度掉到一半時的寬度 | PSF FWHM ≈1.2″ ≈ **6 像素** |
| **noise / σ(雜訊)** | 每個像素的隨機起伏。σ 是它的標準差(典型起伏大小) | — |
| **S/N(訊噪比)** | 訊號 ÷ 雜訊。越高越容易看清楚 | — |

**關鍵換算**:seeing 1.2″ ÷ 0.2″/像素 = **6 像素**。這個「6 像素」之後一直會用到。

## 2. 逐一解釋每個參數

### 2.1 偵測門檻 threshold = 2σ

**它是什麼**:我們掃過每個像素,問「這裡的亮度有沒有明顯高過雜訊?」。門檻 2σ 意思是「**要比雜訊起伏(σ)高出 2 倍才算偵測到源**」。

**為什麼要有門檻**:純天空區也會因雜訊而忽高忽低。若門檻太低,會把隨機的雜訊高點也誤當成「源」。

**為什麼選 2σ**:這是統計上的「假陽性率」(把純雜訊誤判成源的機率):

| 門檻 | 純雜訊超過它的機率 | 評價 |
|---|---|---|
| 0.75σ | **23%** | 太低 → 幾乎在撿雜訊,**物理站不住腳** |
| 1.5σ | 6.7% | 可用但偏低 |
| **2σ** | **2.3%** | **標準、穩健**(天文常用 2–5σ) |

→ **2σ 表示「這個亮度來自純雜訊的機率只有 2.3%」**,夠可信、又是業界標準,所以選它。

> ⚠️ 常見誤區:為了抓暗暈,把門檻一路壓到 0.75σ。但 0.75σ 低於雜訊本身(23% 假陽性),等於「在撿雜訊」,不能辯護。**正解不是降門檻,而是先用下面的 matched filter 把暈變清楚,再用正常的 2σ。**

---

### 2.2 Matched filter,核寬 = seeing(FWHM ≈ 6 像素)

這是整套方法的**核心技巧**,分三步理解。

**(a) 什麼是「smoothing / 平滑」**
把影像「模糊化」:每個像素換成**它周圍鄰居的加權平均**。就像近視或瞇眼看東西,細節被抹平。

**(b) 為什麼平滑能讓暗暈「浮出來」**
關鍵在「雜訊」和「暈」對平均的反應不同:
- **隨機雜訊**:相鄰像素有正有負、彼此獨立 → 平均後**互相抵消,變小**(平均 N 個像素,雜訊降約 √N 倍)。
- **延展的暈**:相鄰像素是同一團平滑訊號、同方向 → 平均後**幾乎不變**。

結果:**雜訊被壓下去、暈保留 → 暈的 S/N 提升。** 原本每像素「暈 < 雜訊」(看不到),平滑後變成「暈 > 雜訊」(看得到)→ 這樣正常的 2σ 門檻就抓得到暈了。

**(c) 什麼是「matched(匹配)」、為什麼核寬 = seeing**
- **核(kernel)** = 平滑用的一小塊權重(高斯鐘形:中間重、周圍輕)。
- **核寬**要設多大?理論(matched filter 定理):**當平滑核的尺度「匹配」你要找的訊號尺度時,S/N 提升最有效。**
- 對點源/一般偵測,標準做法是**把核寬設成 = seeing(PSF FWHM)**。理由:
  - **seeing(6 像素)是影像裡「真實結構的最小尺度」** —— 比 6 像素更細的變化不可能是真天體(都被大氣糊成 6 像素了),那些一定是雜訊。
  - 所以在「6 像素」這個尺度平滑,是「**最大程度壓掉雜訊、又不糊掉任何真結構**」的最佳點。核太小 → 壓不夠雜訊(暈還是抓不到);核太大 → 連真結構的形狀位置都糊掉。

→ 所以 **matched filter 的核寬 = seeing FWHM ≈ 6 像素**,是物理上最有依據的選擇。

---

### 2.3 背景框(background box)要比暈大 → bw = 256 像素

**背景(background)是什麼**:偵測源之前,要先估計並減掉「基準天空亮度」。Source Extractor 的做法是把影像切成**一格一格的方框**,每格算一個「當地背景值」,再減掉。方框大小叫 **`bw`(BACK_SIZE)**。

**為什麼框的大小很關鍵**:
- 想像框在估「這附近正常的亮度是多少」。
- **若框比暈小**:框整個泡在暈裡面,它會以為「這裡本來就這麼亮」→ 把**暈本身當成背景**估出來 → 減掉 → **暈消失了**,偵測不到!(不管門檻多低都沒用,因為暈已經被當背景減掉)
- **若框比暈大**:每個框裡除了暈,還含有**暈周圍足夠的真天空**,才估得出真正的背景基準 → 暈就會明顯高過背景、被偵測到。

**規則**:背景框要**大於你想保留的天體**。這裡暈的直徑 ≈ 226 像素,所以框設 **bw = 256 像素**(比暈大)。

> 這也解釋了之前的一個現象:Source Extractor **預設 bw = 64**(遠小於 226 像素的暈)→ 把暈當背景吃掉 → 怎麼調門檻都抓不到暈。**真正的問題是背景框,不是門檻。**

---

### 2.4 minarea(最小面積)= 1 個 PSF 面積 ≈ 30 像素

**它是什麼**:一個偵測要**至少由幾個相連的像素組成**,才算「真的源」。小於這個大小的就丟掉。

**為什麼需要**:即使用了 matched filter,純天空區偶爾還是有零星幾個像素湊巧超過門檻(那 2.3% 假陽性)。這些是**孤立的小雜點**,不是真源。

**為什麼設 ≈ 1 個 PSF 面積(≈30 像素)**:
- 任何**真實**的天體,因為被 PSF 糊開,至少會佔滿「1 個解析元」= 1 個 PSF 的面積。
- PSF FWHM ≈ 6 像素 → PSF 面積 ≈ π×(6/2)² ≈ **30 像素**。
- 所以「小於 30 像素的偵測」不可能是被 PSF 糊開的真源 → 判定為雜訊、丟掉。
- → **minarea = 30 像素**,物理依據就是「一個真源至少要有一個 PSF 這麼大」。

---

### 2.5 dilation(膨脹)= 往外長 ≈ 6 像素(≈ seeing)

**它是什麼**:偵測完後,把遮罩的邊界**往外擴張幾圈像素**,當作安全邊界。

**為什麼需要**:
1. **門檻以下的翼**:暈的最外圈亮度剛好低於門檻、沒被偵測到,但**仍是真的源光**。若不處理,這圈會被當純天空 → 污染。
2. **PSF 外溢**:亮源的光會被 PSF 糊到邊界外幾像素。

**為什麼設 ≈ 6 像素(= 1 個 seeing)**:PSF 的光大約延伸到 1 個 FWHM(6 像素)之外。所以往外長 6 像素,剛好把這圈「漏網的源光」包進來,又不會過度擴張浪費天空樣本。

---

### 2.6(重要陷阱)雜訊 σ 一定要從「無源區」估

前面門檻用「2σ」,但這個 **σ(雜訊大小)要怎麼算**?

- **錯的做法**:用整張影像(含暈)算 σ。因為暈是一大片偏亮的區域,會把「起伏」撐大 → σ 被高估 → 2σ 門檻變太高 → 反而漏掉暈。
- **對的做法**:**只從「沒有源的區域」估 σ**(統計上叫 sigma-clipping:先把明顯偏亮的像素排除,再算剩下的起伏)。Source Extractor 內建會做這件事。

→ 這是 matched filter 偵測的經典陷阱:**σ 一定要從乾淨天空估,否則暈會自己把門檻墊高、把自己藏起來。**

## 3. 一張總表:參數 → 對應到什麼物理尺度

| 參數 | 值 | 對應的物理量 | 一句話理由 |
|---|---|---|---|
| 偵測門檻 | **2σ** | 雜訊大小 σ | 假陽性僅 2.3%,標準又可辯護 |
| matched filter 核寬 | **6 px** | seeing / PSF FWHM (1.2″) | 在「真結構最小尺度」平滑,最大壓噪不糊真結構 |
| 背景框 bw | **256 px** | > 暈直徑 (226 px) | 框比暈大,才不會把暈當背景吃掉 |
| minarea | **30 px** | 1 個 PSF 面積 | 真源至少有一個 PSF 這麼大 |
| dilation | **6 px** | 1 × seeing | 補暈的翼 + PSF 外溢的安全邊界 |
| σ 的估法 | 排源後估 | 乾淨天空的雜訊 | 否則暈會把門檻墊高、藏住自己 |

**貫穿全部的原則**:**每個參數都對到資料本身的物理尺度(seeing、PSF、雜訊),而不是隨手挑或為了讓數字好看。** 這樣任何一個數字都能對老師/審稿人解釋得清楚。

## 4. 為什麼不是別的做法?(反例)

| 別人可能會做 | 問題 | 我們的正解 |
|---|---|---|
| 把門檻壓到 0.75σ 去抓暈 | 低於雜訊(23% 假陽性),物理站不住腳 | 用 matched filter 把暈變清楚,再用正常 2σ |
| 用 Source Extractor 預設(bw=64) | 框比暈小 → 把暈當背景吃掉 → 抓不到暈 | bw=256(比暈大) |
| 只用單純膨脹(不濾小塊) | 把零星雜訊點也放大成斑塊 | 先 minarea 濾掉小雜點,再膨脹 |
| 用形態學 opening 去雜訊 | opening 會**侵蝕**暗暈的外緣 | 用「按面積刪」(minarea),不縮暈 |
| 用整張影像算 σ | 暈把 σ 撐大 → 門檻太高 → 漏暈 | 排源後估 σ(sigma-clipping) |

---

## 5. 一句話總結

**要可靠地遮住又大又暗的 Hα 暈,不能靠「把門檻壓低」(那會撿雜訊、物理站不住腳),而要:**
1. **背景框設大**(不把暈當背景),
2. **用 matched filter(核 = seeing)把暈的 S/N 拉高**,
3. **再用標準的 2σ 門檻**,
4. **minarea(=1 PSF)去雜訊、dilation(=seeing)補邊**,
5. 全程 **σ 從乾淨天空估**。

每一步都對到資料的物理尺度,所以每個參數都站得住腳、可解釋。
