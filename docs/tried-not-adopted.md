# 試過但沒有採用的做法（2026-08-18 整理）

`src/skymodel/experiments/` 從 60 支精簡到 24 支時刪掉的實驗，這裡記下它們**問過什麼
問題、怎麼設計驗證**，以免同一個題目被重新發明一次。

**先講清楚這份文件的限制。** 那些程式的 docstring 把問題與方法寫得很完整，但
**沒有記錄結果** —— 數字只印在終端機，圖多半在已刪的 `evaluation/` 子目錄裡。所以
下面每一條都能告訴你「當初問了什麼、判準是什麼」，但除非另有註明，**不能告訴你答案
是什麼**。要重做的話程式在 git 裡：

```
git show 665d7a9:src/skymodel/experiments/<名稱>.py
```

已經落地成 pipeline 的結論不在這裡，在 `docs/rejected-approaches.md` 與各 step 的註解。

## 一 天空 basis 怎麼學

現行做法：`step3_sky_basis.py` 對**未加權**的殘差做 SVD，全波段一組 K = 30 條，
全場共用。以下四支各自挑戰其中一個選擇。

### 白化 SVD（`whitened_basis.py`）

未加權的 SVD 挑的是「解釋最多**流量**變異」的方向，最亮的幾條天光線因此吃掉大半
basis；白化之後挑的是「解釋最多**顯著性**的方向」。**ZAP 就是這樣做的**
（`docs/zap-parameters-reference.md` §4 的「變異數正規化」）。

三個變體只差 SVD 之前怎麼縮放通道：不白化（現行）／用 STAT 的 σ／用殘差自己跨
spaxel 的標準差（等價於用相關矩陣而非共變異數矩陣做 PCA）。

設計上刻意只在「學 basis」這一步白化，**擬合一律維持未加權** —— 兩件事分開才知道
差別來自哪一步。

### 雜訊修正的 PCA（`noise_corrected_pca.py`）

和白化不是同一件事：

```
  白化      特徵分解 D^(-1/2) M D^(-1/2)   重新縮放度量,訊號也被扭曲
  雜訊修正  特徵分解 M − alpha·diag(v)      只減掉雜訊底線,訊號方向不動
```

`alpha` 是「STAT 佔真實雜訊的比例」，不硬性設 1 而是掃描讓留出資料決定；`alpha = 0`
就是現行做法。自由度不變（仍是 K 條），所以沒有吃掉源的風險。

### 分波長區段學 basis（`segmented_basis.py`）

ZAP 把光譜切成 11 段各自做 SVD，邊界照 OH 振動帶的族群切。公平的比較必須**固定總參數
數目**：全波段 K 條 vs 分段每段 K/11 條，自由度相同，差別只在「基底能不能跨段耦合」。

### 分空間區學 basis（`regional_basis.py`）

問的是 blank 殘差裡有沒有「非全場共有」的空間結構 —— MUSE 的 slice 沿特定方向排列，
切片級的系統性正好會產生這種形態。

**這三支的驗證都是樣本外的**：spaxel 隨機分成 train / test，basis 只用 train 學，
分數只在 test 上算。理由寫在 `regional_basis.py` 裡：分區一定會讓「用來學 basis 的
那些 spaxel」殘差變小，那只是自由度變多。這個設計值得保留。

## 二 blank 區怎麼擬合

現行做法：`fit_blank` 預設**未加權最小平方**（`run_pointing.sh` 沒有傳
`--blank-chi2`，14 顆的 `meta.json` 都記著 `blank_weight: unweighted`）。程式自己
承認 chi2 才是「統計上正確的權重」，選未加權是為了速度 —— 設計矩陣不隨 spaxel 改變，
`pinv` 只算一次就能解完所有乾淨的 spaxel。

### 兩階段擬合（`blank_two_stage.py`）

天空的兩個成分在兩個區域各自可測，而現行做法把它們混在一起解：

```
  line1 外   連續譜主導,天光線 basis 幾乎不可分辨(該區設計矩陣病態) -> 量 s 的最佳位置
  line1 內   天光線主導,basis 的能量幾乎都集中在這裡                -> 量 cₖ 的最佳位置
```

兩階段是兩區都用但各解各的：線外解 `d ≈ s·C_sky`（1 個參數，極良態），線內解
`d − s·C_sky ≈ Σcₖ·Lₖ`。兩個設計矩陣都不隨 spaxel 改變，速度優勢仍在。

### chi2 式的指標（`chi2_metric.py`）

**這一支記的是一個方法論陷阱，值得單獨記住**：先前所有比較都用未加權的量（rms、
逐通道散布），但未加權擬合的目標函數就是「最小化未加權平方誤差」—— 拿同一個東西當
指標，它當然贏。那不能拿來證明加權擬合比較差。

`chi = R/σ` 問的是不同的問題：殘差相對於該通道的雜訊有多大 —— 那才是決定「一個微弱源
能不能在這個通道上被偵測到」的量。

### 係數圖的空間平滑（`blank_smooth_coef.py`、`coef_spatial_stats.py`）

`coef_spatial_stats` 先量兩件事決定平滑值不值得做：相鄰兩格的差當雜訊下限、自相關
長度當平滑核的上限，x（沿 slice）與 y（跨 slice）分開量。

`blank_smooth_coef` 的留一格驗證有一個明確的尺規：排除中心格、只用鄰居預測它，
若真值在局部近似常數，誤差應為

```
  err ≈ σ_n · sqrt(1 + 1/k) ≈ 1.06 · σ_n     (k ≈ 7 個有效鄰居)
```

接近 1.06 代表鄰居把雜訊以外的都預測到了，平滑安全；遠大於代表有鄰居預測不到的真實
結構，平滑會抹掉它。

它同時記了一個判準上的陷阱：**不能用 blank 殘差當判準** —— 未平滑就是讓殘差最小的解，
任何平滑都必然讓它變大，那個判準的結論必然是「平滑有害」且毫無資訊。所以改用對
ESO nosky 的指標。

## 三 非線性的天空模型（`nonlinear_sky.py`）

現行模型的強度是線性的。這一支試的是把波長偏移與 LSF 寬度也放進去：

```
  S(p, λ) = Σᵢ Aᵢ(p) · Lᵢ(λ − δ(p) ; w(p))
```

**它記下了一個非做不可的設計決定**：basis 必須放進迭代一起重學。如果拿一組「從未
對齊的資料學來的 basis」再在上面加 δ，而偏移真的存在，那組 basis 早就用額外的成分把
它吸收了（描述「有些 spaxel 偏左、有些偏右」），事後再加 δ 必然找不到東西 ——
它要找的東西已經在 basis 裡了。

## 四 誤差還剩什麼

### 線內誤差的分佈（`channel_error.py`）

線外殘差落在雜訊底線上，線內才是和 ESO 有差別的地方。問的是：線內剩下的誤差平均分布
在所有線內通道（那就是雜訊，沒得改），還是集中在少數幾條線（那就可行動）。

拆法不依賴 STAT：`mean(c)` 是同調誤差（雜訊會被平均掉，顯著不為零只能是系統性的模型
誤差），`std(c)` 是雜訊加上逐 spaxel 的變化。

### 線的形狀（`line_shape.py`）

檢驗「線性的強度 basis 表達不了線的形狀變化」。在每條亮線的窗口內把該線的平均輪廓及其
導數當基底：`P` 是強度誤差、`P'` 是波長偏移（一階展開，長得像一正一負的雙峰）、
`P''` 是 LSF 寬度變化、常數是局部連續譜殘留。先做 QR 正交化再投影。

### 遮罩邊界的階梯（`boundary_step.py`）

**這一支的結論寫在 docstring 裡，是可用的**：

> 遮罩**裡面**源的光由模板接走、不進 sky_model 所以留下來；遮罩**外面**整個擬合結果
> 都當天空扣掉。真實的源光在邊界上是連續的，處理方式卻在邊界上跳變，所以殘差必然出現
> 階梯。**膨脹消不掉它，只能把它推到源夠暗的地方** —— 階梯高度永遠等於該半徑處還剩
> 多少源光。

所以「膨脹要多遠」不是美感問題，是「長到多遠才低於雜訊」，而那可以量。

## 五 已經落地的那幾支

以下的結論**已經在 pipeline 裡**，程式刪掉不影響結論的保存，但「為什麼是這個值」的
掃描數字沒有留下。

| 實驗 | 落地成什麼 |
|---|---|
| `clip_threshold.py` | `step3_sky_basis.py` 的 `CLIP_SIGMA = 30` |
| `outlier_reject.py` / `outlier_fill.py` / `outlier_chi2_jump.py` | 學 basis 之前先剔除離群值（`step3_sky_basis.py:246-260`） |
| `mean_estimator.py` | `mean_sky` 用 **sigma-clipped mean**（`step3_sky_basis.py:195`） |
| `measure_seg_thresh.py` | 見 `docs/rejected-approaches.md`：不再自己量門檻，改用教授交付的 seg |

`clip_threshold` 的 docstring 記了一個判準上的觀點值得留著：門檻不是靠「設大一點比較
安全」來選，而是看資料裡有沒有一道間隙 —— 真實的 spaxel 間變化到多少 σ 為止、壞值從
幾 σ 開始。間隙夠寬的話門檻放在裡面任何位置結果都一樣，**那就不是一個要調的參數**。

`mean_estimator` 記了換估計量要看的東西：不是「mean_sky 好不好看」，而是它往下決定的
三樣（`C_sky`、線偵測的 σ、`line_mask`）有沒有變。

## 六 一次性的回答

`sky_vs_source.py` 回答教授的提問「how much of that is sky continuum?」，把一個源的
光譜拆成 observed / C_sky / observed − C_sky 三條畫在一起。動機是 step4 的圖畫的是
已扣過天空的 `observed − 1.0·C_sky`，那條線的高度容易被誤讀成「源本來就這麼亮」。
