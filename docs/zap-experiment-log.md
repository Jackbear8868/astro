# ZAP 實驗記錄(Haro11 MUSE cube)

> 本檔記錄我們對 ZAP(Zurich Atmosphere Purge, Soto+2016)在 Haro11 MUSE 資料上做過的事、量到的數字、以及幾個意外結論。
> 對應程式:`src/run_zap_compare.py`(主流程)、`src/tune_nevals.py`(成分數掃描)、`src/cgm_halpha.py`(CGM 分析)。
> 產出在 `results/zap/`(大檔,已被 `.gitignore` 排除,僅本機留存)。

---

## 0. 一句話總結
**ZAP 本身運作正常,但「餵對 cube」是關鍵:**
- ZAP 的正確輸入是**還含天空的 `wsky`** → 能把天空線扣到接近 MUSE 的 `nosky` 真值、且保留源。
- 對**已扣過天空的 `nosky`** 跑 ZAP 是無效操作(沒天空可學,只會灌雜訊)——這不是 bug。
- **源遮罩是否涵蓋整個延展星系,決定 ZAP 會不會把源吃掉**(這是最關鍵的實作細節)。

---

## 1. 資料與設定
- **cube**:`Haro11_wsky.fits`(含天空)、`Haro11_nosky.fits`(MUSE 已扣天空),WFM,499×559×3679,λ 4750–9348 Å,含 STAT(逐 voxel 變異)。
- **galaxy**:Haro11(blue compact galaxy),z≈0.0206,Hα 觀測 ~6699 Å,有大範圍延展電離氣(CGM)。
- **流程**(`run_zap_compare.py`):`crop → mask → zap → collect → figs`。先在 300×300 裁切版試,最後跑整張 499×559。

---

## 2. 做過的事(時間軸)

### 階段 A — 第一次跑(300² 裁切 + 原始遮罩)
- 原始 `cmd_mask`:白光 2σ 門檻 → 源遮罩只涵蓋 **8.3%**。
- 對 `nosky` 與 `wsky` 都跑 ZAP(各 ~28 分鐘,ncpu=1,自動選 ~51–56 個特徵譜)。
- **結果不如預期**:
  - 源被吃掉:源 spaxel 的 Hα 峰 **63000 → 18000(掉 ~70%)**。
  - 空白殘餘反而變糟:blank 中位 std **2.71 → 16.90**;天空線 std 5577 `9.91→73.45`、6300 `7.27→39.40`。

### 階段 B — 診斷
- Hα 窄帶影像顯示:Haro11 的延展電離氣覆蓋視場 **>3σ 達 21%、>5σ 達 17%**,但遮罩只遮 8.3%。
- 被當「空白天空」拿去建 PCA 的 spaxel,其 Hα 90 百分位 = **19.4**(雜訊 σ≈2.2)→ 約一成「天空」樣本其實滿是星系發射線。
- **根因**:遮罩太小 → ZAP 把 Hα 當天空學起來、扣掉 → 源被削、空白區灌入 Hα 形狀殘差。

### 階段 C — 修遮罩(fix #1)
- 重寫 `cmd_mask`:**Hα 窄帶 + 白光雙重偵測 → 去單點雜訊 → 連通塊過濾 → 膨脹安全邊界**。
- 遮罩涵蓋:300² 版 **31%**、整張版 **44%**。
- 空白區殘餘 Hα 90 百分位 **19.4 → 1.9**(≈雜訊 σ),天空基底乾淨了。

### 階段 D — 用好遮罩重跑(300²),仍有殘留問題
- 源保真大幅改善:Hα 峰 **63000 → 51000(只掉 ~18%)**。
- 但空白殘餘**還是變糟**:
  - line-free 純雜訊(每 spaxel) **1.30 → 2.65**(翻倍)。
  - 天空線中位殘餘被**過扣成負**:5577 `0.13 → −46.4`、6300 `−0.02 → −41.7`。
  - 源 Hα 積分通量保留 **80.6%**。

### 階段 E — 成分數掃描(`tune_nevals.py`)
- 用 ZAP `interactive` 模式算一次 SVD,再用 `reprocess()` 快速掃 nevals = 3…55。
- 發現**任何成分數都救不了**:即使 N=3,line-free 雜訊仍 2.90、天空線 5577 std 高達 915(raw 10.6)、Hα 保留僅 89%。
- → **排除「過擬合 / 成分太多」假說**。問題不在超參數。

### 階段 F — 關鍵轉折:餵對 cube
- 重新檢視:`nosky` 的空白譜本來就**平的**(MUSE 已把天空扣到 ~0),ZAP 沒有「天空訊號」可學,只能擬合並重新注入雜訊。
- 改驗 **正確用法 = 對 `wsky`(含天空)跑 ZAP**,拿 `nosky` 當 MUSE 真值對比 → **全部對上**(見 §3)。

### 階段 G — 程式修正
- `cmd_mask`:Hα 偵測版(見階段 C)。
- `cmd_figs`:把 **wsky+ZAP vs nosky 真值** 設為主驗證圖(`fig5`);原本的 nosky+ZAP 降級為標註清楚的 **null test**(`fig1–3`),並修正量化輸出。
- 新增 `crop full` 模式(整張視場);`collect` 支援「nosky 只當參考真值、不必跑 ZAP」。
- 補上 docstring 漏掉的 `crop` 步驟與正確用法說明;更新 README。

### 階段 H — 整張視場(499×559)
- 整張 ZAP on `wsky`:**3899 秒(~65 分鐘)**,記憶體峰值 **43.7 GB**(無 OOM),自動選 **53** 個特徵譜。
- 遮罩涵蓋 44%,留 ~140k 乾淨 blank spaxel 給 ZAP。

### 階段 I — CGM Hα 分析(`cgm_halpha.py`)
- 比較 MUSE(`nosky`)與 ZAP(`wsky`)兩種扣天空法對外圍 CGM 的影響(見 §4 的意外結論)。

## 3. 關鍵成果:ZAP 在 `wsky` 上有效(整張視場)

| 空白天空指標 | `wsky` 原始(含天空) | **`wsky` + ZAP** | `nosky`(MUSE 真值) |
|---|---|---|---|
| 天空線 5577Å(中位) | 252.7 | **0.62** | 2.30 |
| 天空線 6300Å(中位) | 175.1 | **−0.26** | 0.45 |
| 天空線 8400Å(中位) | 463.9 | **1.26** | 1.08 |
| line-free 純雜訊 | 5.71 | **1.70** | 1.30 |
| 源 Hα 積分通量 | — | **保留 124%** | (100%) |

→ ZAP 把天空線從 ~250–460 壓到 ~0–1.3(基本還原 MUSE 的扣天空),且**保留源**。主圖 `results/zap/fig5_zap_validation.png`。
(300² 裁切版結論一致:天空線 267→1、噪音 5.71→1.70、源保留 110.6%。)

## 4. 意外結論

1. **「最直覺的輸入」是錯的。** 直覺會把已扣天空的 `nosky` 餵給 ZAP「再清一次殘差」,但這反而**把源吃掉、灌入雜訊**。ZAP 需要「還有天空訊號」才有東西學;`nosky` 沒有。

2. **這不是超參數能修的。** 成分數從 3 掃到 55 都救不了 `nosky` 的過扣 → 證明是**輸入問題不是調參問題**。很容易誤把它當成「ZAP 壞了 / 要調 nevals」而鑽錯方向。

3. **源遮罩是成敗關鍵,且白光門檻會嚴重低估。** 用白光 2σ 只遮 8%,但延展電離氣覆蓋 ~31–44%;遮罩不足直接造成 **70% 源流量損失**。改用 Hα 窄帶偵測 + 膨脹後,源損失降到 ~18%(裁切)/源保留 124%(整張)。

4. **對 faint CGM,MUSE 的 `nosky` 反而比 ZAP 乾淨。**(CGM 分析,`fig6`/`fig7`)
   - 兩者都還原出星系 + 到 ~20–30″ 的 Hα halo。
   - 外圍每-spaxel 雜訊:`nosky` **1σ≈13.8** vs `wsky+ZAP` **≈35.5**(ZAP 約 2.5× 噪)。
   - 大半徑(>35″):`nosky` 中位略轉**負**(MUSE 輕微過扣);`wsky+ZAP` 維持**正**,但那正偏移落在天空曝光的**矩形足跡**內,**較可能是扣天空殘差而非真實 CGM**。
   - → 不能簡單說「ZAP 揭露了更多 CGM」;ZAP 的價值在於**能獨立(不依賴 pipeline)重現扣天空**,不在於更深。

5. **源保留 >100%(110–124%)不是 bug。** ZAP 把源遮罩起來、不拿它建天空基底,故在亮源上扣得較「溫和」、不過扣;反觀 MUSE 在亮源可能略過扣。對保留微弱延展訊號而言,寧可略保留也不要過扣。

## 7. 已知限制
- **只有 1 個含天空的 cube(`wsky`)** → 只能做「單曝光重建」,無法測跨曝光泛化。
- ZAP 在天空線波長的殘餘 std 略高於 MUSE(經驗式 PCA 的正常特性)。
- CGM 大半徑的正偏移帶有足跡形狀的系統性,尚未釐清是否可校正。
- `nosky` 的 null test 只在 300² 做過,整張版未補(價值低,故略過)。
